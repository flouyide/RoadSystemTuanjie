01概览与设计原则

这套系统把「画一条路」拆成两个彼此独立的问题：拓扑（谁连着谁）和几何（形状长什么样）。拓扑存在一张图里并序列化进场景，几何则是每次按需从图上重新解算出来的派生数据——不落盘、不入场景，随时可丢弃重建。

五条贯穿全代码的设计决策：

决策做法理由（代码可验证）
只用直线 + 圆弧PathElement 仅两个子类 LineElement / ArcElement圆弧的横向偏移仍是同心圆弧、直线的偏移仍是平行线，车道边线永不 pinch 自交；求交是 O(1) 闭式解（ArcIntersections），无需迭代。贝塞尔两条都做不到。
double 精度 2DDVec2（自有 double 向量），XZ 平面计算，Y 只用于渲染抬升城市尺度（km 级）下 float 求交会抖动；DVec2.cs:8 注释明确此意图。转 float 只发生在写入 Mesh 顶点那一刻。
Profile 是图的边0 宽横截面线 = 边；RoadSegment/Intersection = 节点与直觉相反但更简洁：路段和路口是同一类东西（都是"若干 profile 的汇合"），共享 profile 天然表达连接，断面信息只存一份。
显式存车道Profile.Lanes[] 是 LaneDef 数组，不靠"车道数×宽度"推断支持人行道/车道/绿化带混排、每车道独立宽度与朝向、路缘高度。
网格是派生数据子物体 HideFlags.DontSave，仅 graphJson 字符串进场景Undo/Redo 自动生效（Unity 只需回滚一个 string 字段）；场景文件不膨胀；换机器/换版本重新生成即可。
一句话总结数据流：鼠标 → 地面点 → 两个 Profile → ProfileConnector 解出 PathChain（线+弧）→ PathSampler 离散化 → SegmentMeshBuilder 横向布点成 Mesh → 挂到临时子物体。图变了就重跑后半段。

03数据模型

全部状态收敛在三个容器里：RoadGraph（邻接表图）、Profile（图的边）、RoadNodeBase 派生（图的节点）。几何 PathData 是计算产物，不作为持久状态。DVec2 贯穿所有坐标。

核心约定

类型关键约束与语义
DVec2全系统坐标统一用 double；X→世界X、Y→世界Z。PerpLeft = 逆时针转 90°（世界 +Y 上视角的"左"）。仅写入 Mesh 顶点时才转 float。
Profile图的边，0 宽横截面线，只存数据不渲染。Lanes[] 自左缘到右缘有序；Left = Direction.PerpLeft 决定左缘。HasSameLayout 在 MVP 中要求相连两 profile 等长断面（车道数、序列、宽度逐一相等）。
RoadSegment恰好 2 端口（起止 profile）。Path（PathChain）为 L1 解算缓存，[NonSerialized]。
IntersectionN≥3 端口（MVP 支持 3 叉 T / 4 叉十字）。LaneLinks 显式存车道级转向连接（意图显式，不靠推断）。网格生成本版未实现（见第 10 章）。
PathChain直线/圆弧 PathElement 序列，整体首尾 G1 连续（位置+切向连续）。由 ProfileConnector 生成，作为 RoadSegment 缓存。
为什么 Profile 是"边"而不是"节点"？ 一条路段的形状由两端断面共同决定，共享同一个 profile 的两个路段天然相连——省掉"连接关系"这一层冗余数据，断面信息（车道布局）只存一份。路段和路口在图上都是"若干 profile 的汇合点"，统一为 RoadNodeBase。

系统提供两条等价的建造入口，共用同一套几何解算与网格生成：

05几何解算内核

L1 几何层全部是纯 C#、O(1) 闭式解，可在 Unity 外独立验证。入口 ProfileConnector.Connect 接收两个 profile（中心、方向、车道布局），输出一条 PathChain。等长 profile 只需对中心线解一次——其余车道边线由同一圆心旋转出同心弧得到（这是选"圆弧"而非"贝塞尔"的根本收益）。

5.1 连接判定树（ProfileConnector）

5.2 单 fillet（Fillet.Solve）

采用文章 3 的 two-line fillet 变体：一个切点固定（A 侧），另一个切点 M 在 B 的延续线上求解。设两延续线交点为 C、到 C 的距离分别为 CA/CB：取 CB 上 M 使 CM = CA，过 M、A 作垂线交于圆心 O；全等三角形 OCM ≌ OCA 保证圆在 A、M 两处同时相切。符号约束：C 必须在 A 射线前方（tA ≥ 0）且位于 B 射线后方（s ≤ 0），否则返回 null 交由 Hermite 拆分。输出 Arc(A→M)+Line(M→B) 或对称形式。

5.3 路径采样（PathSampler）

元素采样策略
直线 LineElement按 MaxLineStep=2.0m 等分步长细分
圆弧 ArcElement弦高误差控制：Δθ = 2·acos(1 − ε/r)，保证弦高 ≤ 误差容限 sagitta
输出 PathPoint每点含 Position / 单位切向 Tangent / 累计弧长 ArcLength（供 UV.v 与里程计算）
首元素起点、后续元素起点与上一末端去重（start = first ? 0 : 1），保证点位连续不重叠。

5.4 求交工具（ArcIntersections）

LineLine / LineArc / ArcArc 全部为 O(1) 闭式解，供路口交汇检测使用。当前无调用方，为 M4 路口几何预留（代码中明确标注"严禁贝塞尔迭代求交"）。

06网格生成

SegmentMeshBuilder.Build 把 PathChain 采样后，沿每个采样点的左向单位向量按 LaneDef 宽度横向布点成 Mesh。圆弧偏移仍是同心圆弧、直线偏移仍是平行线——车道边线永不 pinch 自交，这是选圆弧表示的几何根因。

6.1 三段顶点布局

部件生成内容
① 车道顶面每条车道一条环带；人行道顶面抬到 CurbHeight。每采样点左右两点，三角带缝合。
② 路缘竖面人行道与车行道交界：从 y=0 升到 CurbHeight 的竖直面；法线朝车行道一侧（独立顶点保证硬边光影）。
③ 外缘立面道路两侧边缘从顶面落到 y=0，产生厚度感；外侧法线朝外。

6.2 UV 与索引

  • UV.u = 横向归一化 (b[lane]/W)，0=左缘、1=右缘，便于对齐车道标线 atlas。
  • UV.v = 弧长 / 贴图周期 texturePeriod（默认 6m），使路面贴图沿前进方向平铺。
  • 索引使用 IndexFormat.UInt32（支持 >65k 顶点的长道路）。
  • 必须 RecalculateBounds()，否则程序化网格会被视锥剔除误杀。
预览与正式落地共用同一份 SegmentMeshBuilder.Build：运行时（RoadPlayerBuilder）与编辑器（RoadPlacementTool）的预览、RoadNetworkBehaviour.RebuildSegment 的落地都走这里，所见即所得。

07序列化与增量重建

7.1 序列化链路

只有 RoadNetworkBehaviour.graphJson（一个 JSON 字符串）进场景；中间所有几何都是派生数据，不入场景、可随时丢弃重建。

方向调用链
保存（编辑后）CommitEdit() → RoadGraphJson.ToJson(Graph) → RoadGraphMapper.ToDto → JsonUtility.ToJson → 写入 graphJson
加载（OnEnable / Undo 还原）RoadGraphJson.FromJson(graphJson) → RoadGraphMapper.FromDto → RoadGraph（Dictionary 经 List 中转以适配 JsonUtility）
DTO 转换放在 L0（RoadGraphMapper），保持 L0 无引擎依赖；真正调用 JsonUtility 的 RoadGraphJson 在 L2（唯一引用 UnityEngine 的序列化桥）。

7.2 重建策略（RoadNetworkBehaviour.Update）

7.3 增量机制

  1. 编辑（AddSegment/RemoveSegment/MoveProfile 等）调用 NotifyAffected，把受影响节点 Id 收集进集合，并为这些节点的 DirtyVersion++，再触发 Changed 事件。
  2. RoadNetworkBehaviour.OnGraphChanged 把受影响的 Id 加入 dirtyNodes。
  3. 下一帧 FlushDirty：取出并清空 dirtyNodes，仅对其中节点 RebuildNode。
Undo/Redo 自动生效：Unity 只需回滚 graphJson 一个 string 字段；Update 检测到 graphJson != appliedJson 即 RebuildAll，重新反序列化并重建全部子物体。

10已知限制与风险

类别现状与风险
路口网格未实现。RebuildNode 对 Intersection 直接跳过；LaneConnection.Path 缓存字段已留但无生成逻辑。MVP 只渲染路段。
求交工具ArcIntersections 已就绪但无调用方，路口交汇检测（M4）尚未接入。
断面一致性MVP 要求相连 profile HasSameLayout（等长断面）。不支持变宽路、匝道渐变、不同道路类型相接。
纵向高程段内 Y 仅取起点 profile 的 pa.Y（鼠标点击处地面高度）整体抬升，段内无沿程 Y 插值，跨坡道路会呈台阶/斜面。无地形贴合。
撤销范围运行时（RoadPlayerBuilder）无 Undo；仅编辑器工具走 Undo.RecordObject。
递归深度MaxDepth=2，极端 S 形 / 多折弯可能触发深度上限返回 null（编辑器应阻止该放置）。
外部存储仅 graphJson 随场景保存；无独立工程文件导入导出。
精度几何全程 double，仅写顶点时转 float——城市尺度下安全；极端 km 级长直线仍建议分段的常规做法。
