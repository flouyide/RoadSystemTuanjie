路径：Assets/RoadSystem/Runtime/RoadPlayerBuilder.cs 类型：MonoBehaviour（Play 模式） 宿主：RequireComponent(RoadNetworkBehaviour) 输入：Unity Input System

0. 它是什么

这是运行时（Play 模式）画路的脚本，挂在 RoadNetworkBehaviour 同一物体上（第 18 行 [RequireComponent]）。它和编辑器层的 RoadPlacementTool 是"双胞胎"——交互语义几乎一致（单击放起点 → 实时预览 → 再单击连段 → 链式延伸），但有三个本质区别：

维度RoadPlacementTool（编辑器）RoadPlayerBuilder（运行时）
运行时机编辑态，[EditorTool]Play 模式，MonoBehaviour
输入来源Scene 视图事件（OnToolGUI）Input System（InputActionReference）
地面检测射线 ∩ y=0 数学平面（不读地形）Physics.Raycast 打 groundMask（读地形 Y）
朝向指定支持拖拽 ≥2m 定向 + 15° 角度吸附不支持拖拽；首点取相机前向，后续取弦向
Undo有（Undo.RecordObject）无；仅有 DeleteLastSegment
额外能力无Delete（删最后一段）、gridSnap
关键认知：本脚本同样不做几何计算。它只采集输入 → 调 net 的图 API（PlaceProfile/AddSegment/RemoveSegment/RemoveLooseProfile）→ 用与正式落地相同的 ProfileConnector.Connect + SegmentMeshBuilder.Build 画预览。"所见即所得"的来源与编辑器工具一致。

2. 生命周期入口

Awake（68–75 行）

  1. net = GetComponent<RoadNetworkBehaviour>()——拿到同物体上的图宿主（RequireComponent 保证存在）。
  2. cam == null → Camera.main。
  3. groundMask == 0 → LayerMask.GetMask("Ground")：未配置时自动取 Ground 层（若该层不存在则返回 0，后续 GroundPoint 走 y=0 回退）。
  4. EnsurePreviewObjects()：建好预览 GO 与材质，避免首帧延迟。

OnEnable（77–87 行）

  • 若 positionActionRef 或 clickActionRef 为 null → Debug.LogError 提示去 Inspector 拖入。
  • 依次 Enable() 四个 action（Point/Click/Cancel/Delete）。

OnDisable（89–98 行）

Disable 四个 action，SetPreviewVisible(false) 隐藏预览。注意：不清 pendingStart——禁用再启用会保留上次的待连起点（与编辑器工具 OnDisable 清空状态不同）。

OnDestroy（288–294 行）

销毁预览 mesh / GO / 两个材质，防运行时泄漏。

3. Update 主循环（100–113 行）

每帧入口，被 #if ENABLE_INPUT_SYSTEM 包裹。

if (!buildEnabled || cam == null || ClickAction == null) return;
if (ClickAction.WasPressedThisFrame())  OnLeftClick();
if (CancelAction != null && CancelAction.WasPressedThisFrame()) CancelPending();
if (DeleteAction != null && DeleteAction.WasPressedThisFrame()) DeleteLastSegment();
if (pendingStart != null) UpdatePreview();
三个要点：① 首行三重门（开关 / 相机 / Click 动作）任一不满足就整帧跳过；② 三个动作都用 WasPressedThisFrame()（Input System 的边沿检测），天然"每按一次触发一次"，无需手动去重；③ 只有 pendingStart != null 才跑预览——没有起点就不该有虚影。

4. OnLeftClick：提交逻辑（117–167 行）

  1. GroundPoint(out pos, out groundY) 求地面点；失败（射线未命中且无 y=0 回退）直接 return。
  2. pos = SnapPos(pos)；roadY = groundY + roadYOffset——把地形高度 + 抬高量算好，待会儿写进 Profile.Y。
  3. 分支 A（pendingStart == null，放起点）：
    • FindLooseEnd(pos) 找 3m 内既有悬空端。
    • 命中 → pendingStart = loose，pendingStartIsNew = false（复用，不建新 profile）。
    • 未命中 → net.PlaceProfile(pos, DefaultDirection(), DefaultLanes())，并立刻 pendingStart.Y = roadY，pendingStartIsNew = true。
  4. 分支 B（pendingStart != null，放终点并连段）：
    • 距起点 < minSegmentLength（1m）→ return 忽略。
    • reused = loose != null && loose.Id != pendingStart.Id——后半句排除自环。
    • 复用 → end = loose；否则 dir = ComputeEndDirection(pos) → net.PlaceProfile(pos, dir, 克隆车道) → end.Y = roadY。
    • seg = net.AddSegment(pendingStart, end)；null → 警告并 return（pendingStart 不变，可原地重试）。
    • pendingStart = end；pendingStartIsNew = !reused——链式延伸靠这句。
  5. 末尾 lastPreviewKey = null：强制下一帧重建预览（因为起点/终点刚变）。
与编辑器工具的核心差异：运行时没有"拖拽定向"。起点朝向用 DefaultDirection()（相机前向投影），终点朝向用 ComputeEndDirection()（弦向或后方强制同向）。所以运行时画路是"自动朝向"，编辑器工具才允许手动拖出弯曲。

决策树

5. CancelPending / DeleteLastSegment

CancelPending（169–177 行）

只有 pendingStartIsNew 才 net.RemoveLooseProfile（已挂节点的 profile 内部会拒绝删除）；然后清空状态、隐藏预览。比编辑器工具少了 Undo——运行时本就无法 Undo，Esc 只清当前待连起点。

DeleteLastSegment（180–187 行）

long lastVer = long.MinValue;
foreach (var n in net.Graph.Nodes.Values)
  if (n is RoadSegment s && n.DirtyVersion > lastVer)
    { lastVer = n.DirtyVersion; lastId = n.Id; }
if (lastId != null) net.RemoveSegment(lastId);
它用 DirtyVersion（每次编辑自增的版本号）挑出"版本号最大"的路段当作"最后一段"删除。这是启发式——DirtyVersion 在重建时也会被 bump，所以严格说挑的是"最近被改动过"的段，而非"时间上最后添加"的段。绝大多数情况下两者重合，但若你改过旧段又删，可能误删刚改的那条。

6. 朝向与默认方向

ComputeEndDirection（190–197 行）

if (Dot(endPos - startPos, startDir) < 0) return startDir;   // 后方半平面→强制同向
double dist = Distance(endPos, startPos);
return dist > 0.1 ? (endPos - startPos).Normalized : startDir;  // 否则弦向

预览与提交共用此函数（第 237 行也调它），保证"虚影朝向 == 落地朝向"。

DefaultDirection（200–209 行）

首点默认朝向：取 cam.transform.forward 的 XZ 投影，长度 >0.3 才归一化采用，否则回退 DVec2.UnitY（+Z）。即"朝镜头看的方向铺路"，俯视太狠（前向几乎垂直地面）时退化为 +Z。

7. UpdatePreview 预览管线（213–257 行）

  1. EnsurePreviewObjects()。
  2. GroundPoint(out endPos, out _)：用当前鼠标求终点（out _ 丢弃 y，因为预览高度用起点 Y）。失败 → 隐藏 return。
  3. endPos = SnapPos(endPos)。
  4. dist / behind / bad = behind || dist < min。
  5. 帧合并（227–229）：指纹只含 endPos + bad（注意：不含朝向，因为朝向由位置唯一决定）。相同就 return。
  6. dist < min → 隐藏 return。
  7. endDir = ComputeEndDirection(endPos)；造两个临时 profile：tmpA（起点，tmpA.Y = pendingStart.Y）与 tmpB（终点，Y 未设，默认 0）。
  8. ProfileConnector.Connect(tmpA, tmpB) 解几何；null → 隐藏。
  9. SegmentMeshBuilder.Build(...) 出 mesh；预览 GO 放到 (X, pendingStart.Y + previewLift, Y)（贴起点地形高度），换 mesh、按 bad 选红/青材质、显形、销毁旧 mesh。
预览的朝向与编辑器工具不同：运行时没有拖拽定向，所以预览朝向永远走 ComputeEndDirection（弦向 / 后方强制同向），不会出现编辑器工具那种"拖 2m 后按 15° 吸附"的预览。这是两套工具交互语义差异的直接体现。

函数行要点

与编辑器工具不同：运行时预览 GO 是普通 GameObject（没有 HideFlags.HideAndDontSave），因为它活在 Play 模式的场景里，随物体销毁即清理（OnDestroy 兜底）。编辑器工具的预览物体则标了 HideAndDontSave 以免污染场景。

9. 工具函数

FindLooseEnd（298–310 行）

looseEndSnap <= 0 直接返回 null（关闭吸附）；否则遍历 LooseEndProfiles()，跳过自身，取 3m 内最近的一个。逻辑与编辑器工具一致。

SnapPos（312–317 行）

gridSnap <= 0.001 → 原样返回；否则按步长 Math.Round(x/s)*s 取整。没有 Ctrl 临时禁用——运行时没有键盘事件上下文，网格吸附要么开要么关（靠 gridSnap 字段）。

GroundPoint（319–344 行）—— 与编辑器工具最关键的区别

Ray ray = cam.ScreenPointToRay(PointAction.ReadValue<Vector2>());
if (groundMask == 0 || !Physics.Raycast(ray, out hit, 2000f, groundMask))
{
    // 未配置地面层 / 没命中 → 回退 y=0 平面
    p = (hit0.x, hit0.z); y = 0f; return true;
}
p = (hit.point.x, hit.point.z); y = hit.point.y; return true;
这是运行时比编辑器工具强的地方：用相机屏幕射线打 groundMask 层，命中就把地形 Y 写进 Profile.Y（第 135 / 154 行），正式落地的道路 mesh 因此会贴着地形高度。编辑器工具的 GroundPoint 只算 y=0 数学平面，永不设 Y。但当 groundMask==0（Ground 层不存在）或射线没命中任何地面物体时，运行时也回退到 y=0 平面——这点与编辑器工具行为收敛一致。

10. 端到端串一遍

  1. 物体激活 → Awake 取 net/cam/groundMask，建预览对象 → OnEnable 启用 4 个 Input Action。
  2. 每帧 Update：点左键 → OnLeftClick：GroundPoint 打地形拿 Y → 分支 A 落悬空 profile（写 Y）；移动鼠标 → UpdatePreview 每帧用同套几何/网格画青色虚影，高度贴起点 Y。
  3. 再点左键 → 分支 B：ComputeEndDirection 定朝向 → PlaceProfile（写 Y）→ AddSegment → pendingStart 前移成新端点，可无限续接。
  4. AddSegment 触发 RoadGraph.Changed → RoadNetworkBehaviour.Update 检测 JSON 变化 → ProfileConnector 解几何 → PathSampler 采样 → SegmentMeshBuilder 出正式 mesh（用两端 Profile.Y，贴地形）→ 挂到 DontSave 子物体。
  5. 右键/Esc → CancelPending 清待连起点；Delete → DeleteLastSegment 删最近段。

11. 值得注意的问题

1. 预览的终点 Y 缺失（坡度上预览错位）。第 240 行 var tmpB = Profile.Create(endPos, endDir, pendingStart.Lanes); 之后没有设 tmpB.Y（起点 tmpA.Y 在第 239 行设了）。而 ProfileConnector 用两端 Y 决定路径高度，所以预览整条按 pendingStart.Y 拉平。地形有坡度时，虚影是平的、落地后是斜的，二者不一致。修法：第 240 行后加 tmpB.Y = roadY;（需让 UpdatePreview 也拿到 groundY，目前 out _ 丢弃了）。
2. 无拖拽定向，弯道只能靠"分段弦向"近似。运行时每点一个位置，朝向取弦向或后方强制同向，无法像编辑器那样拖出平滑大弧。连续点击密铺可近似曲线，但单段曲率受几何内核的 fillet 限制。若想要运行时也支持拖拽定向，需要额外记录按下点并加 DragDirThreshold 判定（编辑器工具已有现成实现可移植）。
3. DeleteLastSegment 是启发式，非严格栈。依赖 DirtyVersion 最大者，改过旧段后删可能误删。若要严格"撤销最后添加"，应维护一个内部 List<string> 记录添加顺序，Delete 弹栈。当前实现在"只加不改"的工作流下正确。
4. 比编辑器工具正确的地方：读地形 Y。运行时 GroundPoint 走 Physics.Raycast 并把命中 Y 写进 Profile.Y，正式道路 mesh 贴合地形；编辑器工具永远 y=0。若同一套路网在编辑器里画、运行时显示，Y 会不一致（编辑器画的段 Y=0，运行时画的段有地形高）。
